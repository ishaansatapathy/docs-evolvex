The Evolvex API enforces authentication across all routes according to the caller's operational context.

## Authentication mechanisms

| Scheme | Target Surface | Header / Credential |
| :--- | :--- | :--- |
| **Workspace Webhook Auth** | `POST /webhooks/signoz` | HTTP Basic Auth: `evolvex:<workspace-password>` |
| **GitHub HMAC Signature** | `POST /webhooks/github` | `X-Hub-Signature-256: sha256=<hex_digest>` |
| **Machine-to-Machine Token** | `/api/v1/sdk/*`, `/api/mcp` | `Authorization: Bearer <EVOLVEX_API_KEY>` |
| **Browser Session Cookie** | Web UI and `/trpc/*` routes | `Cookie: session_token=...` with `x-evolvex-csrf: 1` |

---

## 1. Webhook authentication (SigNoz alerts)

SigNoz notification channels authenticate using standard HTTP Basic Auth. The username is fixed to `evolvex`, and the password is your organization's unique vault secret:

```bash
curl -X POST "https://evolvex-api.ishaandev.co.in/webhooks/signoz" \
  -u "evolvex:your-workspace-generated-password" \
  -H "Content-Type: application/json" \
  -d '{"status":"firing","alerts":[{"status":"firing","labels":{"alertname":"p99 latency spike"}}]}'
```

<Note>
  Evolvex stores a SHA-256 hash of this password in the database (`secret_hash`), enabling $O(1)$ tenant resolution without decrypting secret tables.
</Note>

## 2. Machine-to-machine bearer tokens

Automated incident remediation scripts, CI/CD runners, and the Telemetry Intelligence collector agent authenticate using Bearer tokens:

```bash
curl -X GET "https://evolvex-api.ishaandev.co.in/api/investigations" \
  -H "Authorization: Bearer ${EVOLVEX_API_KEY}" \
  -H "Content-Type: application/json"
```

Configure your token in the shell:
```bash
export EVOLVEX_API_KEY="evx_live_9b82f019c4..."
```

## 3. GitHub webhook HMAC-SHA256 signatures

GitHub push events are authenticated by computing an HMAC-SHA256 digest of the request body using your configured `GITHUB_WEBHOOK_SECRET`:

```text
X-Hub-Signature-256: sha256=d57946461f76481f075d77f6b8ff4350f48f4565708832f3e8280f2ab7514914
```

Evolvex performs a constant-time comparison on the computed digest to protect against timing attacks.

---

## 4. Browser sessions and CSRF protection

For security, browser requests originating from the Next.js web application rely on hardened, `httpOnly` session cookies combined with a custom header:

```text
Cookie: session_token=...
x-evolvex-csrf: 1
```

Requests lacking the `x-evolvex-csrf` header or originating from untrusted domains are rejected with `403 Untrusted request origin`.
